## 1. Применение HTTP-заголовков

Remnawave поддерживает два способа применения HTTP-заголовков к профилям подписки.

### Способ 1 — Глобально (для всех приложений)

В панели администратора Remnawave откройте **Подписка → Настройки → Заголовки ответа**.
Добавьте нужные заголовки — они будут возвращаться всем клиентам при каждом запросе подписки.

Для **Внешних сквадов** заголовки настраиваются отдельно для каждого сквада: **Пользователи → Внешние сквады → Заголовки**.

### Способ 2 — Точечно для Prizrak-Box через Правила ответов

Правила ответов позволяют применять заголовки только тогда, когда запрос поступает от конкретного клиента,
определяемого по заголовку `User-Agent`. Это позволяет отправлять настройки именно для Prizrak-Box,
не затрагивая другие приложения.

Откройте **Подписка → Правила ответов** и создайте новое правило.
**Добавьте его в начало списка** для обеспечения приоритета.

<Aside type="note">
Полная документация по Правилам ответов Remnawave: [docs.rw/learn-en/routing-rules](https://docs.rw/learn-en/routing-rules)
</Aside>

Prizrak-Box представляется заголовком `User-Agent` следующего формата на всех платформах:

| Платформа | User-Agent |
|-----------|------------|
| Desktop | `prizrak-box/{версия} (Desktop Build; {ОС} OS; Prizrak-Core {ядро})` |
| Android | `prizrak-box/{версия} (Android Build; Prizrak-Core {ядро})` |
| Apple | `prizrak-box/{версия} (Apple Build; Prizrak-Core {ядро})` |

Например, `prizrak-box/1.0.21-beta06 (Desktop Build; Windows OS; Prizrak-Core v1.19.32-r1)`.

Условие `prizrak-box/` подходит для всех платформ. В старых версиях строка начиналась
с префикса `Clash-Meta/` (`Clash-Meta/Prizrak-Box (...)`), поэтому правило с условием `Clash-Meta/Prizrak-Box (` перестанет
срабатывать на новых версиях — используйте `prizrak-box/`.

Используйте следующий JSON как шаблон — он охватывает все заголовки, поддерживаемые Prizrak-Box:

```json
{
  "name": "Prizrak-Box",
  "description": "Заголовки для клиентов Prizrak-Box",
  "enabled": true,
  "operator": "AND",
  "conditions": [
    {
      "headerName": "user-agent",
      "operator": "CONTAINS",
      "value": "prizrak-box/",
      "caseSensitive": false
    }
  ],
  "responseType": "MIHOMO",
  "responseModifications": {
    "headers": [
      {
        "key": "profile-logo",
        "value": "https://example.com/logo.png"
      },
      {
        "key": "announce-url",
        "value": "https://t.me/your_channel"
      },
      {
        "key": "fallback-domain",
        "value": "backup.example.com"
      },
      {
        "key": "pxa-latency-dots",
        "value": "1"
      },
      {
        "key": "pxa-simple-mode",
        "value": "1"
      },
      {
        "key": "pxa-global-mode-mp",
        "value": "1"
      },
      {
        "key": "pxa-conns-view-mp",
        "value": "1"
      },
      {
        "key": "pxa-rp-mp",
        "value": "1"
      }
    ]
  }
}
```

Удалите ненужные заголовки. Описание каждого заголовка — в разделе
[Поддерживаемые заголовки](/ru/for-devs/supported-headers/).

## 2. Кастомный шаблон Mihomo

Чтобы отдавать Prizrak-Box полностью кастомный Mihomo-конфиг — например,
с прокси группой **Smart** — укажите `subscriptionTemplate` в Правиле ответа:

```json
{
  "name": "Prizrak-Box Smart Template",
  "description": "Кастомный шаблон Mihomo с прокси группой Smart для Prizrak-Box",
  "enabled": true,
  "operator": "AND",
  "conditions": [
    {
      "headerName": "user-agent",
      "operator": "CONTAINS",
      "value": "prizrak-box/",
      "caseSensitive": false
    }
  ],
  "responseType": "MIHOMO",
  "responseModifications": {
    "subscriptionTemplate": "SmartPrizrak"
  }
}
```

<Aside type="note">
Полная документация по Правилам ответов Remnawave: [docs.rw/learn-en/routing-rules](https://docs.rw/learn-en/routing-rules)
</Aside>

Значение `subscriptionTemplate` (`SmartPrizrak` в примере) должно совпадать с именем шаблона,
настроенного в панели Remnawave.

Подробнее о типе прокси группы Smart и параметрах её конфигурации — в разделе
[Прокси группа Smart](/ru/for-devs/smart-proxy-group/).

## 3. Шифрование конфигов методом AGE

Remnawave может зашифровать Mihomo-конфиг с помощью age перед отправкой клиенту Prizrak-Box.
Расшифровать и применить конфиг сможет только клиент, у которого есть соответствующий секретный ключ.

Полное руководство по настройке — генерация ключей, конфигурация правила ответа в Remnawave
и настройка клиента Prizrak-Box — в разделе [Шифрование AGE](/ru/for-devs/age-encryption/).

## 5. Описания прокси и групп

Prizrak-Box показывает короткое описание рядом с сервером или прокси группой в списке прокси.
Делайте его не длиннее **30 символов** — таков лимит поля в панели Remnawave.

### Описание сервера (прокси)

Задаётся в настройках хоста в панели Remnawave:

<Steps>

1. Откройте хост на редактирование.
2. В блоке **Опции** нажмите **Добавить**.
3. В разделе **Подписка** выберите пункт **Описание сервера**.
4. Введите текст (не больше 30 символов) и сохраните хост.

</Steps>

Prizrak-Box читает его из ключа `serverDescription` прокси в подписке.
Remnawave отправляет этот ключ только клиентам, которых он узнаёт, а `User-Agent`, начинающийся с
`prizrak-box/`, входит в их число, поэтому дополнительная настройка не нужна.

### Описание группы

Описание прокси группы добавляется в шаблон Mihomo, как и другие параметры групп,
с помощью ключа `description`:

```yaml
proxy-groups:
  - name: 👻 Prizrak
    type: select
    description: Лучшая локация автоматически
    proxies:
      - 🇩🇪 Germany
      - 🇫🇮 Finland
```

Описание группы показывается в строке группы, если она вложена в другую прокси группу.

Все ключи и правила отображения описаны в разделе [Описания прокси и групп](/ru/for-devs/proxy-descriptions/).
